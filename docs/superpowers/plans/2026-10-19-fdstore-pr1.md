# fdstore PR 1 — PID 1 fdstore + lossless broker restart — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `schema-ctl restart dbus` (and so a broker update) on a live system no longer disconnects any system-bus client.

**Architecture:** PID 1 gains a generic fd store (`fdstore.h`). Opted-in services send fds with `FDSTORE=1`/`FDNAME=`, remove them with `FDSTOREREMOVE=1`, and get them back on the next start after their `listen=` sockets. The store survives restarts and PID 1 re-exec. It is dropped on stop, dormant, excised or removal. On SIGTERM, schema-dbus drains, writes a snapshot of its bookkeeping into a memfd, stores the memfd plus its listening socket and every client fd, and exits. Started with those fds, it restores from the snapshot and removes them from the store. Crash resume (live tables, mid_read/mid_write) is PR 2 and out of scope.

**Tech Stack:** C99, header-only modules, existing `make test` C tests + `.github/ci-python-suite.sh`, schema-vmtest skill for the VM, blakbox for hardware.

**Spec:** `docs/superpowers/specs/2026-10-19-fdstore-design.md`

## Global Constraints

- PID 1 learns nothing about D-Bus: fdstore deals in svc name, fd name, fd. Nothing else.
- Opt-in: `.svc` key `fdstore=N`, 0..4096, default 0. With 0, fds sent with a notify message are closed, as today.
- Restart, crash-restart, PID 1 re-exec and config reload keep the store. Stop, dormant, excised, removal from config and system shutdown drop it (close every fd).
- PID 1 never polls stored fds.
- `fdstore=N` sets `NOTIFY_SOCKET` without changing readiness (`ready_path` still gates `dbus.svc`).
- `LISTEN_FDS` order: `listen=` sockets first (names `<svc>.socket`, as today), then stored fds in insertion order, each with its `FDNAME`.
- Notify control buffer sized for SCM_MAX_FD = 253 fds. The broker sends ≤ 253 fds per datagram.
- Broker fd names: `listen` (listening socket), `state` (snapshot memfd), `conn` (each client socket, in snapshot order), `pfd` (fds received with a partial inbound message, in snapshot order).
- Snapshot: magic `0x53444253` ("SDBS") at offset 0, `uint32_t version` at offset 4, version 1. An unknown version → start fresh, closing every stored fd.
- Drain on SIGTERM: at most 2000 ms. A connection whose outbound queue is not empty by then is dropped (normal remove_conn), not stored.
- No automatic restart in the RPM. No change to the "schema-dbus only at reboot" memory rule in this PR.
- Kill lines: broker round trip no measurable regression; broker RSS < +1 MB; PID 1 RSS unchanged beyond noise with no fdstore users; boot time unchanged beyond noise (blakbox ×3).
- Every new layout carries a version (snapshot version above; reexec adds a record type, no format bump, because older images ignore unknown records).
- Hardware tests of a live broker restart are announced to Jonathan before running.
- Never `git commit -a` in this repo (boot-history.csv is deliberately uncommitted); add files by name. Run `make test`, `LC_ALL=C make test` and `.github/ci-python-suite.sh` before pushing.

## Review Focus

1. **A service exits right after sending FDSTORE.** SIGCHLD and the notify datagram arrive in the same poll round. Expected: fds stored, not lost to a reap that ran first → Task 3 drains notify before reap. Pinned by the Task 6 harness (store-then-exit).
2. **A non-opted service, or a stranger, sends fds.** Expected: fds closed, nothing stored, PID 1 fd count unchanged → Task 2/3 tests.
3. **Store over cap.** Expected: excess fds closed, a log line, the earlier ones kept → Task 1 test.
4. **PID 1 re-exec while a store is held, including falling back to the old image.** Expected: new image keeps the fds. An old image ignores the records and closes them → Task 4 tests.
5. **Broker restart while a client is mid-send of a large message, and while a reader is stuck.** Expected: the partial message completes after resume. The stuck reader is dropped alone after 2000 ms → Task 6 harness cases.

**Interfaces:**
- Produces:
  - `typedef struct { char svc[64]; char name[64]; int fd; } fdstore_ent;`
  - `extern`-free globals inside the header (static): `fdstore_ent *fdstore_v; int fdstore_n, fdstore_cap;` (heap, grown by doubling, NULL when empty, so zero RSS when unused)
  - `int fdstore_valid_name(const char *name)`: 1 if 1..63 chars of `[A-Za-z0-9_.-]`
  - `int fdstore_add(const char *svc, int fd, const char *name, int max)`: 0 stored; -1 refused (fd closed). Refused when `max <= 0`, the svc already holds `max`, the total reaches 4096 (`FDSTORE_MAX_TOTAL`), or the name is invalid. A NULL/empty name stores as `stored`.
  - `int fdstore_remove(const char *svc, const char *name)`: closes and removes every entry of svc with that name, returns the count
  - `int fdstore_drop(const char *svc)`: closes and removes all of svc's entries, returns the count
  - `int fdstore_count(const char *svc)`
  - `int fdstore_collect(const char *svc, int *fds, const char **names, int max)`: insertion order, returns n
  - `void fdstore_set_cloexec(int on)`: all entries
  - `typedef int (*fdstore_keep_fn)(const char *svc, void *ctx);` and `int fdstore_sweep(fdstore_keep_fn keep, void *ctx)`: drops every svc for which `keep` returns 0, returns fds closed
