# Timers (audit 4.9) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `randomized_delay_sec=` and a richer, multi-line `on_calendar=`, so imported timers keep their schedule and stop piling up at 00:00.

**Architecture:** A pure header `calendar.h` (masks per field, day walk) replaces the calendar helpers in service.h. service.c parses up to 4 specs plus the delay; engine.c arms through one jitter helper and shows the next fire. The importer translates the systemd forms the blakbox census uses.

**Tech Stack:** C99 static PID 1, Python 3 importer, sh live test via schema-user.

**Spec:** `docs/superpowers/specs/2026-11-17-timers-design.md`

## Global Constraints
- Grammar `[DOW] [DOM] H:M`; DOW names 3-letter or full, lists, `a..b` ranges (wrapping not allowed); DOM 1..31 lists/ranges; H 0..23 and M 0..59 each `*`, number, list, range, `a/s`, `*/s`; step 0 refused; seconds never.
- DOW and DOM both given: both must hold.
- Max 4 `on_calendar=` lines; in a drop-in the first one replaces earlier files' list; empty `on_calendar=` ignored.
- Next = min over specs; recent = max over specs; search 8 years (2922 days); a spec with no occurrence in that window refuses the load.
- `randomized_delay_sec=` 0..2678400 whole seconds, added to `timer_next.tv_sec` at every arm; `getrandom(GRND_NONBLOCK)`, fallback CLOCK_MONOTONIC ns ^ FNV of the name.
- Every on_calendar value valid today parses to the same schedule.
- No docstrings; why-comments only.

## Review Focus
1. DST days: a spec at 02:30 on the spring-forward day still fires once that day (mktime normalizes to 03:30), and the fall-back day does not fire twice. Test: Task 1, `test_dst` under America/Chicago.
2. A re-exec or reload must not re-jitter a calendar timer into firing early or twice: carried timer_next is kept. Test: Task 3 live, reload during the wait leaves the fire time printed by status unchanged.
3. `hourly` imported as `*:00` must not fire at arm when armed at :00:xx — strictly after `after`. Test: Task 1, `next(*:00, 10:00:30) == 11:00`.
4. A drop-in that sets `on_calendar=` replaces, not appends. Test: Task 2, base `03:00` + drop-in `04:00` → one spec, hour 4.
5. Catch-up across several specs uses the latest past occurrence. Test: Task 1, recent over [`Mon 03:00`, `*:30`] picks the :30 slot.
