## Greg rulings (2026-10-20 00:05)
fast path: pipes (F_GETPIPE_SZ) + shmem/memfd (F_GET_SEALS) close inline; sockets NOT (TCP linger; AF_UNIX carries in-flight fds). One closer per risky fd (a closer stuck on fd 1 of N left N-1 in PID1's table). Re-exec: fdclose_quiesce waits <=1 s until every closer has exited or sits in close() (/proc/PID/syscall), else refuses; then SIGKILL + reap. <6.16: at cap stop reading notify (backpressure).
unit: fast path no child; 2 stuck fds -> 2 closers, both out of the table; quiesce kills closers in close() <1 s; quiesce refuses (-1, ~1 s) while a closer is not in close(), leaves it; backpressure at cap w/o SO_PASSRIGHTS. make test PASS, vmtest PASS.
Devuan 6.12: 40 attackers -> 28 closers, status 0.015 s, live re-exec with 28 stuck 'ok' (quiesced, killed, 0 left). 60 attackers (62 sent) -> closers capped at 32, status 0.015 s; drained, 0 zombies, 0 failed, restart dbus resumed (18->19).

## fast path removed (2026-10-20 00:10)
Security review: pipe_release takes pipe->mutex, which a writer can hold while faulting on a FUSE-mmapped buffer -> PID1 close of a pipe can block. memfd/shmem eviction not provably lock-free either. Every received fd now gets its own closer, no inline close.
unit + make test + vmtest PASS. Devuan: attack status 0.020 s, live re-exec with closer stuck ok, restart dbus resumed (19->20), 0 failed, 0 zombies.
